# 中文切塊與字元計數

中文的資訊密度比英文高。同樣 1000 個字元，英文大約是 150 到 200 個單詞，中文可以裝進 400 到 500 個有意義的詞。
所以沿用英文語料的 `chunk_size=1000`，中文會切出過大的塊：一塊裡塞了好幾個主題，檢索時整塊一起回傳，
命中的段落被不相關的內容稀釋。

實務上中文語料建議把 `chunk_size` 降到 300 到 500 字元，`chunk_overlap` 抓 chunk_size 的兩成左右。
切點盡量落在 Markdown 標題邊界，因為標題本身就是主題訊號，會一起被算進向量。

## 字元與 token 不是同一件事

用字元數當切塊單位是近似做法。中文一個字通常吃掉一到兩個 token，英文一個單詞平均一點三個 token。
所以同樣 400 字元，中文耗掉的 token 明顯多於英文。若模型的 context 很緊，
應該改用 tokenizer 實際計算，而不是數字元。

## 標點與空白

中文沒有空白分詞，`RecursiveCharacterTextSplitter` 預設的分隔符（`\n\n`、`\n`、空白、空字串）
在中文上會直接掉到「空字串」那一層，變成按字元硬切。補上中文標點作為分隔符（。！？；，）
可以讓切點落在句子邊界。
